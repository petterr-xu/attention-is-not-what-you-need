# Attention Is Not What You Need

> 一款 Mac 端轻量化待办管理应用：把「记住要做什么」这件事交给工具，你只需专注当下。

名字向 [《Attention Is All You Need》](https://arxiv.org/abs/1706.03762)（Transformer 的开山之作）致意，但反其道而行——**注意力不是你所需要的东西**。日常办公总在多任务间并行切换（改需求、回消息、开会……），频繁切换会打散注意力，你不该靠脑力去记住「现在在做什么、待会要做什么」，把这件事交给工具就好。

## 功能

- **待办列表**：手动添加 / 结束 / 删除任务，支持重命名，删除前二次确认
- **当前任务**：点击选中为「当前在做」，开始计时并置顶；再次点击取消选中
- **计时**：当前任务显示本次会话投入时长（切走归零），挂起任务显示挂起时长；超过一天改用 `xx.x day`、超过 29.9 天改用 `xx.x month`，再长就显示 `:(`
- **排序**：当前任务永远第一，其余按挂起时长越久越靠前；睡眠任务一律沉底
- **睡眠**：右键任务可选 sleep——置灰沉底、不计时、不被跨周自动结束，其余操作照常；右键 wake up 唤醒，视作刚创建重新回到挂起态
- **已完成列表**：结束的任务进入独立列表，默认展示当天结束的，可一键放回
- **自动结束**：创建于上一个自然周（或更早）的任务，跨周后自动结束，可手动加回
- **数据持久化**：待办 + 已完成列表存本地 JSON，重启保留；计时状态重启清零
- **更新提示**：自动检查新版本，有新版本时在面板底部显示下载图标（悬停可见版本号）
- **AI 接口（MCP）**：把待办暴露给本机 AI 工具读写，权限分「关闭 / 安全（只读）/ 开放（读写）」三档，默认关闭；菜单里可一键复制客户端配置
- **时长提醒**：挂起或执行中的任务（睡眠的除外）达到设定时长后发一条系统通知，同一段状态只提醒一次；**默认开启**、默认时长 36 小时

## 下载安装

到 [Releases](https://github.com/petterr-xu/attention-is-not-what-you-need/releases) 下载最新的 `Attention-vX.Y.Z.dmg`：

1. 双击打开 dmg，把窗口里的「Attention」拖进旁边的「Applications」文件夹
2. 若提示「已存在同名项目」，选「替换」（升级时会出现）
3. **首次打开**：
   应用未经过 Apple 公证，直接双击启动会被拦下并提示“该应用未经认证”，为打开Attention请不要选择“移到废纸篓”，请点击完成/确认并打开Mac设置->隐私与安全性，在该设置项的底部选择“仍要打开Attention”。

上述操作只需做一次，之后正常双击即可。

**系统要求**：macOS 13+、Apple Silicon（M 系列芯片）。

## 使用

启动后**没有 Dock 图标、也不会弹窗口**，去屏幕顶部菜单栏点击清单图标即可打开面板。

- **菜单栏面板**：点击顶部菜单栏的清单图标弹出
- **右键菜单**：右键点击菜单栏图标，可切换悬浮窗、自动结束跨周任务、任务时长提醒、允许 AI 控制、配置 MCP 客户端、检查更新、查看版本、退出应用
- **悬浮窗**：默认在屏幕右上角，可折叠成圆形浮标、可拖动、**可拖右下角手柄调大小**（宽高都能调，尺寸会记住）；面板底部「显示悬浮窗」开关控制显隐
- **添加任务**：输入框输入后回车
- **切换当前任务**：点击任务行
- **结束** ✓　**放回** ↩　**删除** 🗑（二次确认）　**重命名** ✎（回车保存）
- **睡眠 / 唤醒**：右键任务行 → `sleep` / `wake up`

## 给 AI 用（MCP）

Attention 内置一个 [MCP](https://modelcontextprotocol.io) 接口，配好之后可以直接让 AI 帮你读、甚至整理待办。

### 权限分三档

在**右键菜单栏图标 → 「允许 AI 控制」**里切换，**默认「关闭」**：

| 档位 | AI 能做什么 |
|---|---|
| 关闭 | 什么都做不了，任何调用都会被拒绝 |
| 安全（只读） | 只能查：列出待办、看当前在做、看已完成 |
| 开放（读写） | 可查可改：新建、重命名、设为当前、sleep / wake up、结束、放回、增改子任务 |

**任何档位下 AI 都不能删除任务**——删除不可逆，接口里就没有这个能力。

### 怎么配

右键菜单栏图标 → **「配置 MCP 客户端…」**，弹窗里给出两段可直接复制的文本：通用的配置 JSON，和 Claude Code 的命令。命令里的路径是**按当前 app 的实际位置现算的**——从 `build/` 跑和从 `/Applications` 跑不一样，写死会指到一个不存在的地方。

Claude Code 一条命令：

```bash
claude mcp add --scope user attention -- "/Applications/Attention.app/Contents/Helpers/attention-mcp"
```

`--scope user` 让它对所有项目生效（默认的 `local` 只对当前项目生效）。加完用 `claude mcp list` 确认是 `✔ Connected`——`add` 成功只表示配置写入了，不代表连得上。

其他客户端（Claude Desktop / Cursor 等）用通用的 `mcpServers` 片段，点弹窗里的「复制 JSON 配置」。

### 几点说明

- **app 必须在运行**。没跑的话 bridge 会返回明确错误，不会自动帮你拉起。
- **改完配置要重启客户端会话**才生效。
- 从 dmg 拷出来的 helper 可能带 `com.apple.quarantine`，被客户端启动时会被 Gatekeeper 拦下。弹窗会检测到并给出 `xattr -dr` 的解除命令。
- 原理：app 内开一个只限本机同用户的 Unix domain socket，`attention-mcp` 只是做协议转换的薄壳。所有变更都在 app 主线程上执行，所以 AI 改了什么，你的面板会实时跟着变。

## 时长提醒

挂起或执行中的任务晾太久时提醒你一下。**睡眠中的任务不参与**（它本来就是「先放着」的）。

- 右键菜单 → **「任务时长提醒」**子菜单里有两项：**「打开任务时长提醒」**（开关，默认开启）和**「时长设置…」**（默认 36 小时）。打开开关时会请求通知权限。
- **时长设置**里是天 / 小时 / 分钟三个框，各配上下箭头（上限 60 天 / 24 小时 / 60 分钟），也可以直接输入；**边输边校验**，填错的框会标红、不让保存。
- 设置时长**不会**顺手把开关打开——开关没开的话，保存后会提示你去菜单里打开它。关掉开关也**不会**丢掉已配的时长。
- 首次纳入观察（app 启动、或你刚打开这个开关）时如果已经有超时任务，只发**一条汇总**，不会一次刷你一屏。
- 之后运行期间，每个**新**跨过阈值的任务单独提醒一次；**同一段状态只提醒一次**——切走再切回、唤醒后会重新计时，那时才会再提醒。
- 把时长调小**不会**补发已经提醒过的任务。

两点要知道：

- 通知里会出现**任务名**（超过 20 个字会截断），所以它也会进系统通知中心。任务名敏感的话留意一下。
- 这个 app 用本地自签（未公证），**每次重新构建后系统可能把它当成新 app、通知授权会失效**。开发期如果发现收不到通知，去 系统设置 → 通知 里重新允许即可。

## 常见问题

- **看不到菜单栏图标**：请以 `.app` 方式运行（`open` 打开），纯命令行 `swift run` 不显示菜单栏图标
- **退出应用**：右键点击菜单栏图标 → 「退出 Attention」；或在终端执行 `pkill Attention`
- **数据存在哪**：`~/Library/Application Support/Attention/tasks.json`

## 开发

需要 macOS 13+ 与 Swift 工具链（构建与运行无需完整 Xcode）。Swift/SwiftUI 原生实现，Swift Package Manager 构建，无第三方依赖。

```bash
./build.sh                    # 产出 build/Attention.app
./release.sh 1.0.1            # 构建 + 打包 + 创建 GitHub Release
./release.sh 1.0.1 --dry-run  # 只打包不上传
./test.sh                     # 跑单元测试（需完整 Xcode，见下）
```

单元测试用 swift-testing 编写。默认工具链 Command Line Tools 缺少 SwiftPM 测试所需的模块搜索路径与运行库，因此 `./test.sh` 会用 `DEVELOPER_DIR` 指向完整 Xcode 后再执行 `swift test`——不需要 sudo 改 `xcode-select`，也不影响用 CLT 打包 App。

各脚本的完整用法见文件头部注释。
